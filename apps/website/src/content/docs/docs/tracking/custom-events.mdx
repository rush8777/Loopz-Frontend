---
title: Custom events
description: Mark important product outcomes, such as a project being created or an invitation being accepted.
---

Automatic tracking can show that someone clicked a button. A custom event tells Movcues what the product actually accomplished. Product teams use these events to measure milestones such as creating a first project, accepting an invitation, or completing checkout.

## Example: measure a successful export

A click on **Export** only tells you that someone pressed the button. Record `report_exported` after the report has been created successfully, so your team can measure completed exports rather than button clicks:

```js
async function exportReport() {
  const report = await createReportExport();
  window.analytics.event("report_exported", {
    format: report.format,
    source: "analytics",
  });
}
```

The example is illustrative: your developer connects the event to the function that finishes the export in your product.

## Choose useful details

- Name the result, not the button: use `report_exported`, not `export_clicked`.
- Keep the name consistent so the team can compare the same action over time.
- Add only details that help answer a product question. For example, `format: "csv"` can help show which export format people use.
- Never include passwords, payment details, email addresses, or private text entered by a user.

## When to record it

Record an event only after the action succeeds. For example, send `project_created` after the app confirms that it saved the project, not as soon as someone clicks **Create project**. Events sent before the SDK is ready may be missed; the [Installation guide](/docs/getting-started/installation/) explains how developers can handle that case.
