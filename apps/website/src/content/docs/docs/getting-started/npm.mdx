# ES module setup

The SDK source publishes an ES module entry with the package name `@movcues/sdk`. Its public factory is `createAnalytics`.

```ts
import { createAnalytics } from "@movcues/sdk";

const analytics = createAnalytics({
  siteId: "YOUR_SITE_ID",
  debug: false,
});

analytics.event("app_started");
```

`createAnalytics()` initializes the returned singleton immediately and registers page-lifecycle cleanup. Keep the instance in one application-level module or provider rather than creating one per component.

:::caution
This audit verifies the module source and package manifest, not public registry availability. Confirm that `@movcues/sdk` is published to your approved npm registry before documenting an `npm install` command for your users. Do not use the older `movcues/sdk` import found in some example files; it does not match the shipped package manifest.
:::

## Use the instance

The instance has the same primary methods as the browser global:

```ts
analytics.identify("usr_123", { plan: "pro" });
analytics.event("invite_sent", { method: "email" });
analytics.page();
```

When you control the lifecycle yourself, stop or destroy the instance during teardown:

```ts
analytics.destroy();
```

`destroy()` stops collection, clears in-memory pending events, removes route observers, and releases the module singleton for a later initialization.

## Server rendering

This is a browser SDK. Load it only in client-side code and never initialize it during server rendering. See the [Next.js integration](/integrations/nextjs/) for an example.
