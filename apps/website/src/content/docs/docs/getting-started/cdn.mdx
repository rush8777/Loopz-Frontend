# CDN installation

The CDN bundle is the simplest way to add Movcues to a static site, an app shell, or an existing framework deployment.

## Standard loader

Add this once per HTML document. `async` avoids blocking page rendering.

```html
<script
  async
  src="https://cdn.movcues.com/v1.js"
  data-site-id="YOUR_SITE_ID"
></script>
```

The IIFE bundle installs a queue-capable public API at `window.analytics`, then automatically initializes it from the script element’s `data-site-id` value.

## Optional endpoint

The SDK normally sends to its built-in production endpoint. Only set `data-endpoint` when Movcues has given you a compatible endpoint for your environment.

```html
<script
  async
  src="https://cdn.movcues.com/v1.js"
  data-site-id="YOUR_SITE_ID"
  data-endpoint="https://your-approved-endpoint.example"
></script>
```

:::caution
Do not expose private API URLs, secret keys, or server credentials in this tag. The browser SDK uses a public Site ID, not a server-side credential.
:::

## Queue calls before the bundle loads

If your application needs to call Movcues before the remote script has loaded, create the compatible command queue first:

```html
<script>
  window.analytics = window.analytics || function () {
    (window.analytics.q = window.analytics.q || []).push(arguments);
  };

  window.analytics("event", "pricing_opened", { source: "header" });
</script>
<script async src="https://cdn.movcues.com/v1.js" data-site-id="YOUR_SITE_ID"></script>
```

The loader drains queued commands when it installs. A queued `init` command takes precedence over its automatic script-tag initialization.

## Manual initialization

You may initialize manually when a Site ID becomes available only after your application starts:

```js
window.analytics.init({
  siteId: "YOUR_SITE_ID",
  debug: false,
});
```

Call `init()` once. Duplicate initialization is ignored by the shipped runtime.
