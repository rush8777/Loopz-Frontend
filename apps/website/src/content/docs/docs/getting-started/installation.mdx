Installation connects your website to Movcues so your team can see product activity. For a simple site, use the CDN script. For an app built with React, Next.js, Vue, Svelte, or another build tool, use the ES module. Choose one method and install it once in the shared part of your site.

## Example: measure a new-user journey

Suppose your team wants to understand whether new users reach their first project. After installation, Movcues can record visits and supported interactions automatically. A developer can add a `project_created` event when the project is successfully saved. You can then review the journey in Movcues without adding the installation snippet to every page.

## Install with the CDN

Ask a developer to add this once to the shared page template, before `</head>`. Replace `YOUR_SITE_ID` with the ID for your Movcues site. This ID connects the activity to the right site in your dashboard.

```html
<script
  async
  src="https://cdn.movcues.com/v1.js"
  data-site-id="YOUR_SITE_ID"
></script>
```

The Site ID is public and safe to include in browser code. Do not add passwords, secret keys, or server credentials to the page.

### If your app sends an event before the script loads

Most teams can skip this. A developer only needs a command queue if the app might send an event before the asynchronous script is ready. The queue holds that event briefly and sends it when Movcues finishes loading:

```html
<script>
  window.analytics = window.analytics || function () {
    (window.analytics.q = window.analytics.q || []).push(arguments);
  };

  window.analytics("event", "pricing_opened", { source: "header" });
</script>
<script async src="https://cdn.movcues.com/v1.js" data-site-id="YOUR_SITE_ID"></script>
```

The loader sends queued commands after it loads. If the queue includes its own `init` command, that setup is used instead of the `data-site-id` initialization.

### If your app receives its Site ID later

For example, if your app only knows which site to use after sign-in, a developer can initialize Movcues when that value becomes available. Use this in place of automatic setup with `data-site-id`:

```js
analytics.init({
  siteId: "YOUR_SITE_ID",
  debug: false,
});
```

Initialize once. Additional initialization calls are ignored.

## Install as an ES module

For an app assembled with React, Next.js, Vue, Svelte, or another build tool, a developer can install the package and create one Movcues instance where the app starts:

```bash
npm install @movcues/sdk
```

```ts
import { createAnalytics } from "@movcues/sdk";

const analytics = createAnalytics({
  siteId: "YOUR_SITE_ID",
  debug: false,
});

analytics.event("app_started");
```

`createAnalytics()` starts the SDK. `app_started` is only a sample event; in a real product, track a meaningful action such as `project_created` only after saving succeeds. Keep the SDK instance in one shared place so it is not started repeatedly by individual screens.

:::caution
Before using this method, confirm that `@movcues/sdk` is available in your package registry. The repository contains this package name, but its public npm availability has not been confirmed. Older examples may show the incorrect name `movcues/sdk`.
:::

### Use and stop the instance

The instance can recognize users, record outcomes, and record an explicit page view, just like the CDN version:

```ts
analytics.identify("usr_123", { plan: "pro" });
analytics.event("invite_sent", { method: "email" });
analytics.page();
```

When the app is shut down or replaced, a developer can call `destroy()` to stop collection and release its browser listeners.

Movcues runs in the visitor’s browser. In apps that also render pages on a server, create the instance only on the browser side. See the [Next.js integration](/docs/integrations/nextjs/) for an example.

## Verify the installation

1. Publish the website with the Movcues installation in place.
2. Visit the website and open a page as a normal visitor would.
3. In the Movcues dashboard, choose the same site and open **Observe → Events**. Look for the page view from your visit.

If you don’t see it after a short wait, ask your developer to confirm that the published site contains the script and uses the same Site ID as the dashboard. For more help, see [troubleshooting](/docs/troubleshooting/).
