title: Quickstart
description: Connect Movcues to your product, see the first activity, and track a meaningful user action.
---

Use this guide to get a first view of what people do in your product. The SDK starts collecting basic activity after it is installed. Your team can then add named events for important outcomes, such as creating a project or inviting a teammate.

## Example: check whether onboarding works

Imagine your team wants to know how many new users create their first project. Movcues can record visits and clicks automatically. A developer adds one `project_created` event after a project is successfully created. In the dashboard, your team can then review the journey from visiting the app to reaching that milestone.

## 1. Connect your site

Ask a developer to add the Movcues loader to your website and replace `YOUR_SITE_ID` with the ID for the site you want to measure. The Site ID tells Movcues where this activity belongs.

```html
<script
  async
  src="https://cdn.movcues.com/v1.js"
  data-site-id="YOUR_SITE_ID"
></script>
```

The Site ID is available in your Movcues installation settings. It is safe to use in browser code; never put passwords or secret keys in the page.

## 2. Check for activity

After the updated website is published, visit a page yourself. In Movcues, choose the matching site and open **Observe → Events**. You should see a page view from your visit. The [Installation guide](/docs/getting-started/installation/#verify-the-installation) has simple troubleshooting steps if it does not appear.

## 3. Name an important product outcome

Automatic activity can show that someone clicked a button. It cannot tell you whether the action succeeded. Ask your developer to add an event after an important action completes.

For example, after a user creates a project:

```js
window.analytics.event("project_created", {
  project_type: "marketing_site",
  team_size: 3,
});
```

The event name describes the result, not the button. The extra details help answer questions such as whether a template or team size affects project creation. Use non-sensitive values only.

## 4. Recognize signed-in users

If you need to understand activity by account, your developer can attach the product’s internal user ID after sign-in:

```js
window.analytics.identify("usr_123", {
  plan: "growth",
  workspace_id: "ws_456",
});
```

Use an internal ID rather than a name or email. On sign-out, the app should clear the identity so activity from the next person using that browser is not assigned to the previous account. See [Identify users](/docs/tracking/identify/) for more detail.
